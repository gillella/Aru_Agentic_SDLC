The thesis

The competitive advantage is not the coding model. It is the harness: durable state, executable specs, mechanical gates, independent review, and a learning loop.

The operating path

Seven stages, one durable loop.

Each stage has an accountable owner, a durable output, and a failure mode. Choose a stage to inspect it. With JavaScript disabled, every stage remains visible in sequence.

Stage 01

Intent

Define the problem, outcome, constraints, and non-goals before agents optimize a solution.

Human direction
Durable output

A problem statement with decision ownership.

Control point

Humans own product intent; agents may challenge and clarify it.

If weak

Plausible wrong software arrives at machine speed.

Factory move

Interrogate ambiguity before planning or code.

Stage 02

Research & spec

Turn intent and evidence into living requirements, acceptance scenarios, and dependency-aware slices.

Human + research agents
Durable output

Cited research, PRD/spec, acceptance criteria, and issue decomposition.

Control point

Product validates meaning; agents draft and test completeness.

If weak

Models fill requirement gaps with unreviewed assumptions.

Factory move

Bridge spec tools into issues; do not replace board state with task files.

Stage 03

Board & triage

Use one durable coordinator for Backlog, Ready, claims, dependencies, and review work.

Mechanisms
Durable output

An unblocked Ready issue with explicit scope and file ownership.

Control point

The board survives sessions, crashes, and agent runtimes.

If weak

Agents collide, lose state, or invent parallel lifecycles.

Factory move

Keep one source of truth and enough Ready depth for the fleet.

Stage 04

Isolated build

Claim first, plan high-risk work, then implement each issue in its own worktree.

Any governed agent
Durable output

A focused pull request linked to its originating issue.

Control point

Worktree isolation and declared paths prevent accidental overlap.

If weak

Concurrent changes corrupt shared state and erase attribution.

Factory move

Keep tools pluggable; enforce the same lifecycle contract.

Stage 05

Verify & review

Separate generation from verification through local evidence, CI, scenarios, and a distinct reviewer.

Gates + peer agent
Durable output

Reproducible evidence, resolved findings, and review attribution.

Control point

The author cannot be the sole judge of their own output.

If weak

Green-looking tests and self-review create confidence theater.

Factory move

Design verification that scales faster than line-by-line reading.

Stage 06

Merge & ship

Apply one mechanical Definition of Done, then move an immutable artifact through concrete targets.

Deterministic delivery
Durable output

A governed merge plus artifact identity, target URL, smoke evidence, and reversal path.

Control point

Audit-only deployment records must never imply that a runnable build moved.

If weak

“Merged” is mistaken for “available and healthy.”

Factory move

Keep CI/CD deterministic; agents invoke it rather than improvise it.

Stage 07

Observe & learn

Turn production signals, defects, cost, and cycle time into new board work and better harnesses.

Operator + monitoring agents
Durable output

Telemetry-linked issues and measured harness improvements.

Control point

Operational evidence closes the loop back to intent.

If weak

The factory repeats defects and cannot price its own work.

Factory move

Make every escaped defect a candidate gate or heuristic upgrade.

Honest placement

Strong middle. Open ends.

Aru’s differentiator is already real: any governed agent, one board, mechanical gates. The highest leverage now sits before Ready and after merge—not in adding another coding runtime.

Strong

Execution middle

Claim → worktree → PR → peer review → governed merge has durable orchestration and mechanical gates.

Partial

Front of factory

Intent → research → trustworthy Ready work needs a more complete, repeatable intake bridge.

Weak

Back of factory

Immutable build → real targets → smoke → observe → learn remains the largest product-delivery gap.

Constraint

Review throughput

Independent verification is the binding constraint; evidence quality must scale with implementation volume.

Verified

CI dogfooding

The playbook runs the lint, secret, dependency, boundary, and test gates it ships.

Hardened

History & versioning

Merge history, checkpoints, releases, and pinned consumer references support audit and reversal.

Missing

Unit economics

Tokens, wall time, and review rounds per issue are not yet a reliable operating signal.

Convergent principles

Mechanisms over vibes.

Research and factory audits converge on ten design rules. They are independent of which model or editor happens to execute the work.

Intent is scarce.Clear direction matters more as generation gets cheaper.
Mechanisms beat prompts.Hooks, gates, and typed handoffs outperform longer instructions.
The repository is the knowledge plane.Operational context must be visible where agents work.
Generation and verification are separate.Independent review is ownership, not a bot comment.
Deterministic seams stay deterministic.Delivery and policy engines are invoked, not improvised.
Review is the binding constraint.Verification capacity must grow with code volume.
History and telemetry matter.Audit trails and unit economics make the system steerable.
One process owner.One board and lifecycle prevent contradictory control planes.
Trust is engineered.Layered scenarios, contracts, rollback, and red teams earn autonomy.
Humans handle true exceptions.Risk raises evidence depth, not routine approval count.

Quality system

Trust arrives in layers.

No single check proves a change safe. The factory accumulates independent evidence from intent through production, then feeds defects back into the harness.

1

Spec & local evidence

Acceptance scenarios define done; focused local checks prove the implementation before push.

2

CI & contracts

Lint, secrets, dependencies, tests, and architecture boundaries run outside the author’s narrative.

3

Independent review

A distinct agent owns adversarial inspection, findings, and durable attribution.

4

Merge & deploy safety

One merge gate, immutable artifacts, staged smoke evidence, and governed reversal close the delivery path.

5

Production & learning

Alerts become issues; repeated defect shapes become stronger gates and better heuristics.

Operating model

The expert moves up a level.

The work shifts from writing every line to defining intent, designing verification, codifying knowledge, and steering the line.

Operator

Feeds intent, watches factory state, and handles genuine exceptions.

Harness engineer

Builds skills, scripts, gates, CI, and entropy controls.

Fleet workers

Implement through stable identities and one shared lifecycle contract.

Independent reviewers

Challenge changes from a distinct seat and own review evidence.
